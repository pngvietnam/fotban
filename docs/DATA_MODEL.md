# Milestone 2 data model

## Milestone 5 reusable-content extension

Migration `20261016120000_news_reuse_license` adds NewsPermissionStatus (UNREVIEWED/ALLOWED/RESTRICTED), source commercialReuseAllowed and requiresReusableLicense. Existing explicit approvals are backfilled without granting new access. Article gains licence name/URL, attribution, policy/revision evidence URLs, verification time, commercialReuseAllowed and DAY/INSTANT publication precision. A CHECK requires complete evidence when commercial reuse is asserted; date precision has constrained values. Nullable legacy fields remain intact. One verified CC BY 4.0 Wikinews record now persists; league/club candidates remain disabled. See [WIKIMEDIA_NEWS.md](WIKIMEDIA_NEWS.md).

## Milestone 5 additive news changes

Migration `20261016110000_news_ingestion` adds NewsSource slug/language/country/official/termsReviewed/ingestionMethod and explicit ingestionAllowed/permissionReference/maxExcerptChars controls. The existing `type` is the sourceType. Defaults deny ingestion; a CHECK requires reviewer, review timestamp and a permission reference before ingestionAllowed can be true. Excerpts are bounded to 0–280 permitted characters; a numeric cap does not grant rights. No source is auto-enabled.

Article.publishedAt becomes nullable to represent absent/unparseable dates honestly; a new CHECK still requires a date on published articles. Collection time never substitutes for publication time. ArticleUrl adds a unique URL → Article FK with reverse index, backfilling source/canonical aliases without changing IDs or deleting data. Legacy cross-column collisions cause the transactional migration to abort for editorial resolution rather than merge records silently. A global ingestion advisory lock, existing Article uniqueness and alias keys protect exact URL identity and later canonical discovery.

All earlier checks/triggers are preserved. News sync stores metadata drafts, never full bodies or AI fields, and does not modify reviewed/processed/published article content. See [NEWS_INGESTION.md](NEWS_INGESTION.md) for permission and storage policy. The Milestone 2 sections below describe the original implementation baseline.

The schema and SQL migrations together define the model. Prisma cannot express all PostgreSQL checks or triggers; preserve custom SQL when generating later migrations. No external provider, ingestion, AI, video integration, authentication flow, publication service or social processing is implemented here.

## Identity and time

Internal IDs are UUIDs generated by Prisma; raw SQL clients must supply IDs and updatedAt explicitly. Operational timestamps use timestamptz(3), stored as absolute instants and displayed in Asia/Bangkok by later UI/services. DailyBrief.date and JobRun.logicalDate are editorial calendar dates (`date`), not timestamps; callers must derive them in the editorial timezone. No current season or guessed match statistics are seeded.

League → Season → ClubSeason preserves league membership per season. PlayerClub preserves club membership intervals with a source URL instead of overwriting history. A composite FK prevents Match/ClubSeason from referencing a Season from another League. PostgreSQL checks reject reversed intervals, same-club matches, negative/one-sided score pairs, invalid score ranges and invalid counters. Unknown scores remain null. Extra-time and penalty scores are stored separately; provider adapters must later document whether each vendor's total includes extra time before normalization.

Match and Video use provider + externalId uniqueness. MatchEvent adds matchId because some providers scope event IDs to a match. ExternalIdentity maps League/Club/Player IDs into provider namespaces with exactly one FK target; entityType qualifies external IDs that vendors reuse across entity kinds. MatchStat has one metric per match/club/player/provider/period. Its named unique index uses PostgreSQL `NULLS NOT DISTINCT`, so null playerId still identifies one club-level statistic. Use findFirst + create/update or a matching SQL conflict target for null-player stats; Prisma's nullable compound-unique input cannot express every SQL null target.

## News, citations and revisions

NewsSource stores review/configuration separately from article labels. Source score is not truth probability. Sources start disabled with score zero until reviewed; no fictional source rankings are seeded. Access policy and optional retentionDays record storage permission/retention decisions. Article retains source URL and canonical URL with separate uniqueness; canonicalization, tracking-parameter handling and cross-source URL policy belong to ingestion. Raw/full article storage is nullable: store only licensed text or permitted excerpts, and enforce retention in later jobs.

ArticleCluster groups Article rows while preserving every source record. Representative selection/version and conflict metadata are explicit; merge/unmerge history belongs in AdminAuditLog. ArticleEntity has exactly one Club/Player/League/Match target and one unique association per article/target. Relations use FKs rather than unstructured ID arrays.

ClaimEvidence points to exactly one source Article or Match field. Its optional articleId identifies the processed claim's subject; direct match evidence does not require creating a fake article. A match evidence source must identify fieldPath. Quote preserves source/locator plus original and translated text. AIProcessingRun stores article FK, frozen input snapshot/hash, model/prompt/schema/output versions and validation outcome, without executing any AI. JSON is used for versioned snapshots/results, not follows or entity links.

DailyBrief is unique on date + locale. BriefRevision carries windowStart/windowEnd/cutoff, inputHash, ranking version, publication timestamps and revision number. BriefItem belongs to a specific revision and its DailyBrief through a composite FK; this prevents cross-brief items. Position is unique per revision + section. Item input snapshots are frozen with published content, and BriefItemEvidence is a real many-to-many citation table.

Database constraints reject publication of articles lacking required Vietnamese/classification fields or claim evidence, READY/PUBLISHED revisions with no items or missing citations, and published Brief identities without a published revision. Deferred checks permit an atomic transaction to create the evidence and publish afterward. Published revisions, their items/citation joins and cited evidence are immutable: corrections create new revisions/evidence. These are basic integrity safeguards, **not** the full reliability/factuality/rights checks or editorial publication gates of Milestones 7/11/12. Evidence existence does not prove claim accuracy. Do not expose a public publishing API before those services exist.

Transfer/TransferUpdate preserve player/club context, nullable money/dates and evidence-backed history. Fees use Decimal, never floating point. The mandatory update evidence FK cannot by itself establish official authority; confirmed-transition authorization and correspondence between current status and latest update must be enforced transactionally by Milestone 10. Likewise, the data model does not implement automatic deduplication, clustering, fact validation or ranking.

## Preferences, operations and deletion

User has a unique auth-provider/subject identity and a role; no credentials or session implementation is included. Each UserPreference owns relational UserFollow rows, with exactly one League/Club/Player target and uniqueness per preference/target. User deletion cascades only into private preferences/follows. Target deletion is restricted.

JobRun has a unique jobName/logicalKey, attempts, checkpoint, lease fields, safe error fields and correlation ID. A rerun updates that logical run; it does not create another row. Durable scheduling, lease acquisition, timeouts and retry behavior are later work. ProviderStatus contains health/freshness/checkpoint/error metadata, not credentials.

Domain/content/evidence/Brief relations use ON DELETE RESTRICT. Hide/disable records instead of deleting provenance; corrections append a revision. AdminAuditLog is append-only and intentionally has no updatedAt. Actor deletion is restricted while audit records exist; later account-erasure workflows must anonymize permitted personal fields without deleting audit provenance. Generic audit target IDs are accompanied by before/after snapshots rather than a cascade-prone polymorphic FK. Auth/ownership/admin authorization remain server-side work for later milestones; these tables alone do not grant safe browser database access.

Indexes follow actual FK lookup/filter prefixes: kickoff/league/home-away club, article public/source/story feeds and processing queue, entity targets, evidence references, job status/timestamps and audit targets. Existing compound unique indexes cover leading lookup columns where possible. The Milestone 2 baseline had 52 explicit secondary indexes and 27 compound unique declarations, plus primary/field unique indexes. No speculative JSON/embedding/FTS index is added before its query workload exists.

## Seed, migrations and recovery

The development seed inserts only Premier League and La Liga references by slug. It preserves existing names/metadata on rerun, creates no sources/news/results/users/videos and requires ALLOW_DEV_SEED=true, a loopback football_morning database URL and a non-production NODE_ENV. Do not set the opt-in in production configuration. Production reference provisioning must be separately reviewed.

Two transactional, additive migrations are checked in: the initial schema and a follow-up publication integrity guard. Neither resets nor drops existing application data. `prisma migrate deploy` applies only pending migrations, so repeat deployment is safe. Custom SQL checks, deferrable constraint triggers, immutable-content triggers and null-stat uniqueness are part of the migration contract; a normal Prisma schema diff does not fully audit their semantics. Tests execute these SQL migrations directly in disposable [PGlite PostgreSQL](https://pglite.dev/docs/), separate from DATABASE_URL. Live PostgreSQL 16 migration/seed evidence is recorded in PROGRESS.md.

For later schema changes: back up first, review generated SQL and preserve custom invariants. Prefer additive changes and a corrective forward migration. Do not edit an applied migration or run migrate reset on a database with needed data. Migration commands do not verify backup recoverability for you.

Before production migration, use pg_dump custom format and restore it to a separate disposable database using pg_restore --exit-on-error --no-owner --no-acl. Verify row counts/constraints/application access before switching connections. On Windows, write binary dumps with pg_dump's `-f` argument, not PowerShell text redirection. Keep dumps outside source control, restrict access, and test recovery using the same PostgreSQL major version. Never use a destructive restore against the sole copy of data. If Prisma reports a failed migration, inspect `_prisma_migrations`, take a backup and assess its transaction state before using migrate resolve; do not automatically mark a failure applied. The full production restore drill/runbook remains a Milestone 19 gate.

## Milestone 3 additive extensions

`20261016100000_match_provider` adds only fields/tables needed for normalized free-tier sync: nullable club shortName/TLA/country/venue and externalCrestUrl; typed SEASON/MATCH external mapping FKs and uniqueness; Match provider timestamp/raw status/score-duration metadata; ProviderStatus failure/records/pacing/cooldown fields; and relational Standing rows with season/league/club FKs and provider/season/stage/group/type/club uniqueness. The one-target identity CHECK is extended rather than removed, and existing match primary identities are backfilled into the shared mapping. Existing data is retained and no reset is used.

Standings keep per-row fetchedAt and preserve rows missing from partial responses. Club.logoUrl remains the reusable/licensed asset field; externalCrestUrl is private external metadata and is never used as an automatically licensed image. Score component and UTC normalization conventions are now specified in [MATCH_PROVIDER.md](MATCH_PROVIDER.md). No domain/Brief/evidence integrity checks from Milestone 2 were weakened.
